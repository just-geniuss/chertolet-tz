# Проверка комплекта

Дата: 28.10.2026. Среда: macOS, Python 3.14.7.
Объект проверки: проект спецификации 0.2 после ревью Игнатьевой и Мельникова.

## Воспроизводимые проверки из корня

```bash
python -m compileall -q tests
python tests/check_traceability.py
python -m unittest discover -s tests -t . -v
git diff --check
```

- Компиляция Python-файлов: успешно.
- Трассируемость: успешно — R01–R16, 29 уникальных кейсов с ID в docstring,
  методы и таблицы совпадают, ссылки матрицы сверены в обоих направлениях.
  Наборы входов дают 137 вариантов, включая непараметризованные кейсы.
- Проверка пробелов в изменениях: успешно.
- Запуск unittest в самом репозитории: ошибка импорта `ModuleNotFoundError:
  No module named 'chertolet'`. До выполнения кейсов дело не доходит:
  `chertolet.py` должен создать разработчик. Это не успешная приёмка реализации.

## Дополнительная проверка самих тестов

Для проверки переноса с pytest на unittest вне репозитория была создана временная
контрольная реализация публичного контракта. С ней все 29 методов (137 вариантов)
выполнены успешно. Она не включена в поставку и не заменяет будущую реализацию.
Этот результат подтверждает выполнимость тестов и расчётов, но не качество
отсутствующей реализации разработчика. Скрытых заглушек, skip и подмены импорта
в приёмочных тестах нет.

## Ограничения и следующий этап

Реализацию ещё нельзя принять. Разработчик добавляет `chertolet.py` и повторяет
команды выше без временной контрольной реализации. Результат на Python 3.10
и других поддерживаемых версиях здесь не заявляется. Переполнение суммарного
пути исключено из обязательной приёмки (SPEC §8).
